# 优先级判断表

## P0

满足任一条件即可判定为 P0：

- 阻断主流程，用户无法完成核心任务
- 错误后几乎无法恢复，且影响范围大
- 关键入口不可见或关键结果不可达

## P1

满足任一条件即可判定为 P1：

- 不阻断任务，但明显拖慢效率
- 用户容易困惑、误解、重复操作
- 缺少必要反馈、引导、解释、恢复路径
- 在高频场景中持续造成摩擦

## P2

满足任一条件即可判定为 P2：

- 不影响完成任务，但影响专业感、一致性、可读性
- 样式、文案、图像、品牌使用不规范
- 低频场景下的轻度体验问题
- 需要优化，但不应抢占更高优先级问题

## P3

满足任一条件即可判定为 P3：

- 样式规范或设计系统规范存在轻微偏移，但暂未影响任务完成、理解效率或页面稳定性
- 更像“应收敛的零散偏差”，优先级低于 P0 / P1 / P2，但仍应作为正式样式 issue 记录
- 适合作为 HiUI 视觉专项的维护项、整洁性项或后续统一治理项
- **仅允许用于 `category=样式问题` 的正式 `issues[]` 或 `style_review.hiui_sections` 专项结论**

## 深度问题定级补充

### 可判 P0

- 核心任务链路断裂，用户无法完成主要业务目标
- 状态流转缺失导致任务无法继续，例如驳回后无法修改重提
- 权限错配导致越权访问、敏感数据泄露，或关键角色无法完成职责
- 页面反馈与真实结果相反，例如显示成功但实际失败
- 异常后数据丢失且无法恢复，例如提交失败后清空已填写内容
- 批量、审批、财务、权限等高风险操作无确认且不可恢复
- 创建、提交、发布等核心对象闭环完全断裂，例如无法创建成功、创建后结果不可达、详情不可进入且无替代路径

### 可判 P1

- 不完全阻断任务，但明显增加重复录入、绕路、人工确认或沟通成本
- 某些业务状态缺少对应操作、解释或下一步，但仍有替代路径
- 无权限、禁用、失败、空态等状态缺少原因和解决路径
- 表单字段联动、默认值、必填规则不符合业务预期，导致用户反复试错
- 跨页面入口、返回、编辑、保存后的落点不一致，持续造成困惑
- 批量操作、导入导出、审批处理等复杂任务缺少结果明细或失败明细
- 上下文操作的图标/文案语义与真实动作不一致，用户容易误解为删除、关闭、移除或取消高价值对象
- 高频对象上的可点击、滑动、拖拽、长按、hover 快捷操作缺少可发现线索或反馈，导致用户不知道功能存在或误判为不可用
- 创建/编辑/删除/邀请等任务只验证到入口或弹窗，未能验证提交结果、列表刷新、详情可达、状态变化或回收路径
- 创建成功后对象不出现在预期列表，或需要手动刷新、重新搜索、切换页面才能看到结果
- 删除、撤销、归档后列表、详情、计数或状态没有同步更新，用户需要额外确认真实结果

### 仍判 P2

- 不影响任务完成，只影响可读性、专业感或局部一致性
- 深层风险没有足够证据，只能作为待确认项
- 低频状态的轻微提示不完整，但不影响恢复
- 样式、文案、布局问题未影响理解和操作

### 可判 P3（HiUI 专项层）

- 页面仍明显属于同一套 HiUI 体系，只是存在零散视觉收口空间
- 局部 token、字重、圆角、间距档位轻微漂移，但未形成第二套视觉语言
- 个别组件细节不够齐整，但不会让用户误判状态或迷失主路径
- 图表、卡片、按钮等仍在统一体系内，仅存在轻微一致性噪音

## HiUI 视觉专项定级补充

以下规则用于 `style_review.hiui_sections` 里的 5 类专项结论：

- `全局视觉基线`
  - `P0`：页面已经脱离 HiUI 体系，主结构色、主交互色、敏感语义色严重错乱，直接影响识别或风险判断
  - `P1`：主色、层级、文字灰阶或主体底色关系明显漂移，用户会持续误判主次或状态
  - `P2`：局部颜色、字重、间距、圆角不统一，影响专业感但不影响操作
  - `P3`：轻微零散偏差，建议后续统一收口
- `跨页面共享结构`
  - `P0`：出现第二主工作区、第二主滚动或主阅读流断裂，已经影响核心任务理解
  - `P1`：页头、主区、supporting 区职责混乱，页面明显不像同一产品
  - `P2`：结构边界略松，仍能完成任务，但整体稳定感下降
  - `P3`：轻微结构收口问题，例如局部留白、分区节奏略飘
- `页型规范`
  - `P0`：页型用错导致核心任务承载体失真，例如该全页编辑却硬塞抽屉，或该统计页却退化到无法承载主信息
  - `P1`：页型大体可辨认，但壳层、owner、滚动链或底栏规则明显偏离
  - `P2`：页型内局部视觉语法偏移，如间距、分组、卡片层次不稳
  - `P3`：仅有轻微页型细节偏差
- `组件语义`
  - `P0`：危险语义、主操作语义、关键状态语义错置，用户可能做出错误决策
  - `P1`：主次按钮、状态标签、筛选语法、详情语法明显不一致，持续造成误判
  - `P2`：组件样式不完全齐，但总体语义仍可理解
  - `P3`：轻微皮肤偏差或局部收口不足
- `数据可视化专项`
  - `P0`：图表主题、阅读流或主工作区关系错误，页面已经不像同一产品，且影响读数判断
  - `P1`：图表色板、布局、主次图关系明显偏离，分析路径受干扰
  - `P2`：图表卡片、轴线、顺序色板、收口节奏不够统一，但仍可读
  - `P3`：图表局部主题收口项，可纳入后续统一治理

## 定级边界

- 流程 / 交互类正式 `issues[]` 仍只使用 `P0 / P1 / P2`
- `category=样式问题` 的正式 `issues[]` 可使用 `P3`
- 若某个 HiUI 专项问题已经影响任务理解、状态判断或操作结果，应进入正式 `issues[]`，并按 `P0 / P1 / P2` 定级
- 若只是体系一致性上的轻偏差，也应进入正式 `issues[]`，但可定为 `P3`

## 降级规则

- 仅视觉不统一、但不影响理解和操作：若属于明确规范偏差，优先判 P3；若已影响可读性或专业感，判 P2
- 仅信息密度高、但提升效率：先参考 `ignore-list.md`
- 证据不足时，不直接升到 P0/P1，优先标记为待确认
- 证据不足的深度问题，不直接判 P0/P1；除非已有代码、截图或交互证据能证明主流程受阻
- HiUI 视觉专项若仅为轻微收口项，`hiui_sections` 可记为 `P3`，同时用 `linked_issue_index/title` 指向正式 P3 样式 issue
