# 非典型页面设计原则

## 目标

本文件用于承接完全非典型页面可直接继承的 `hiui-design` 设计原则。

它解决的是：

- 典型页面里哪些稳定原则可以抽出来继续用于完全非典型页面
- 完全非典型页面在不走页面模板时，仍然必须保留哪些共享壳层原语与设计系统边界
- 哪些典型页专属模板合同不能直接带入完全非典型页面

它不解决的是：

- 非典型页面在 `nonTypicalExecutionBrief` 阶段如何保持可执行约束
- 把非典型页面沉淀成页面模板式枚举或新的协调模式目录
- 典型页具体 `baseTemplatePath`、`businessSlots`、`slotBoundaryContract` 如何迁移

## 使用顺序

当页面已经判断为 `non-typical-page` 时，优先按下面顺序使用：

1. 先读 `design-system-first.md`
2. 再读 `shared-page-design-guidance.md`，锁定跨 family 共享的结构与视觉语法
3. 再读本文件，锁定可继承的共享原则与 family 边界
4. 再读 `hiui5-visual-baseline.md`，补颜色、字阶、间距与组件默认值
5. 最后读 `non-typical-ai-generation-guidance.md`，形成最小决策包并决定是否 stop-before-code

## 可直接继承的原则

### 1. 保持统一页面气质

- 页面必须继续看起来像同一套 B 端产品，而不是另一套后台风格
- 结构、信息密度、识别效率与操作稳定性优先于装饰
- 默认视觉关系仍然是“灰底外槽 + 白底主体工作区”
- 没有书面设计依据时，不得用新的卡片墙、重装饰底色、强阴影或彩色结构块替代原有页面气质

### 2. 保持共享壳层原语

- 完全非典型页面仍然必须存在统一 `PageHeader`
- 页面仍然必须存在统一 `whiteBody` 主工作区
- `whiteBody` 仍然是唯一 primary workspace owner，而不是任意白色容器
- 页面级主操作仍然默认位于 `PageHeader` 右侧
- 页面不得出现第二个同级主结构
- supporting region 可以存在，但不能替代 primary region

### 3. 保持统一标题层级

- 页面级标题、区块标题、子分组标题必须继续使用统一层级
- 字号、字重与层级节奏应继续服从 `hiui5-visual-baseline.md`
- 不得为了突出局部模块，额外发明新的标题档位
- 不得让模块标题反客为主，替代页面级标题

### 4. 保持统一组件语义

- 基础组件默认继续只允许 HiUI5、`local-managed-runtime` 公开能力和已批准扩展
- 状态表达、按钮语义、输入控件、卡片/容器边界、常见 Tag 语义应继续保持一致
- 轻量筛选、单字段切换、结构化筛选必须分别回指到 HiUI5 `Tag`、HiUI5 `Tabs`、HiUI5 `QueryFilter` 等正式承载面，不按左右位置粗分
- 不得使用 `div/span + className` 伪造语义组件
- 不得为了图方便引入第三方 UI 组件绕过 `hiui-design`

### 5. 保持统一 token 与 spacing 基线

- 颜色、字阶、圆角、边框、阴影、间距必须回指到 `hiui-design` 与 HiUI 5 基线
- 页面本地样式默认只允许 `layout-only`
- 默认继续使用同一套 spacing scale，而不是按局部视觉感觉自由调整
- 没有明确设计依据时，不得新增页面本地视觉 token

### 6. 图表也必须继续服从 hiui-design 规范

- 非典型页面中的图表不是独立视觉系统；它仍然属于当前页面的设计系统约束
- 若页面包含数据图表，图表的主题、色板、标题字阶、卡片边界、内边距和图表容器节奏都必须回指到 `hiui-design` 规范
- 不得直接使用图表库默认主题、默认色板或高装饰图表卡来绕开页面基线
- 若页面以图表为主信息载体，优先回看 `figma-pages/data-visualization.md` 的图表主题与图表卡规则；若图表只是局部承载体，也仍需服从统一字体、颜色、间距与卡片语义

### 7. 保持单一主阅读流

- 页面必须能够用一句话说清用户从哪里开始、经过哪些主区域、最终完成什么任务
- 页面允许存在主副工作区，但仍然只能有一个主阅读流
- 复杂页面可以增加上下文区、辅助区、检查区，但不能让阅读流变成多个同级起点

## 只能抽象继承、不能直接照搬的内容

下面这些内容可以继承“原则”，但不能直接照搬典型页原文或模板合同：

- `whiteBody` 的存在方式
  原则可继承，但在非典型页中应改写成唯一主工作区 owner，而不是典型页的固定结构布局。
- 操作区语法
  主次操作区原则可继承，但不能照搬某个列表页或编辑页的具体按钮排布。
- 分区节奏
  可以继承“主次分区要清晰、阅读顺序稳定”的原则，但不能直接照搬筛选区、分页区、底栏区顺序。
- 结构 owner
  可以继承“不能出现第二主结构”的原则，但不能照搬典型页的 slot 名称与受控锚点体系。

## 不能直接继承的内容

下面这些内容属于典型页专属模板合同，不应直接带入完全非典型页面：

- `baseTemplatePath`
- `businessSlots`
- `requiredShell`
- `slotBoundaryContract`
- `pageAdjustmentContract`
- 各页型的固定模块顺序
- 各页型的模板锁区与局部改造锚点

这些内容依赖“先命中基础页型、再从模板起步”的前提；完全非典型页面默认不具备这个前提。

## 反模式

出现以下情况时，说明页面正在偏离完全非典型页面的设计原则：

- 通过多层白卡叠加伪造第二 `whiteBody`
- 为了突出复杂度而引入第二套局部视觉系统
- 页面标题、模块标题和局部标题全部失去层级差异
- 页面级主操作下沉到局部模块，导致主任务入口不稳定
- 主副工作区都试图承担“主页面”角色
- 图表直接使用默认主题、默认色板或与页面脱节的高装饰卡片皮肤
- 用“非典型页面”作为理由绕开组件语义、token 基线或设计系统边界

## 与其他文档的关系

- `design-system-first.md`
  负责“先看组件与设计系统，再看页面”
- `shared-page-design-guidance.md`
  负责典型页与非典型页都必须先共享的结构、视觉与设计系统指导
- `generation-principles.md`
  负责典型页与新页型的共性生成原则
- `hiui5-visual-baseline.md`
  负责颜色、字阶、间距、按钮、输入、卡片等默认视觉基线
- `non-typical-ai-generation-guidance.md`
  负责完全非典型页面写代码前的最小决策包与 stop-before-code
- `non-typical-block-design-map.md`
  负责把 `dataShape` 收口成可复用的区块语义、组件承载与图表/排版/间距约束

本文件的职责是：把典型页中可稳定复用到完全非典型页面的那一层原则，抽出来作为 family 级事实源。
