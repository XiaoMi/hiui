# 组件 / 设计系统优先原则

## 这份文件解决什么问题

这份文件定义 `hiui-design` 的第一性起点：先看组件与设计系统，再看页型，再看模板页。

它解决的是下面这个问题：

- 当业务页面形态还没完全固定时，不要先跳到某个具体页模板
- 先确认当前需求落在哪些基础组件、通用容器、视觉基线和交互规则上
- 再把这些规则映射到页型和模板页面

## 角色定位

`hiui-design` 不是只有“页型模板复制”这一层。它同样是一个**组件 / 设计系统驱动**的生成 skill：

- 组件层先定义可复用的按钮、表单、筛选、表格、详情、抽屉、布局基线
- 页型层再把组件组合成可识别的页面语法
- 模板层最后才落到具体示例页复制改造

`src/components/hiui-design-runtime` 在当前体系里要单独看待：

- 它是受管公共组件层，不是普通业务组件目录
- 它承接的是典型页壳、宿主桥接、字段映射、查询筛选和详情/表单页壳这类公共运行时能力
- 这层物料由接入脚本和受管生成链统一物化、升级和校验，不由单个业务页面各自改写
- 业务页面只负责消费这层公开能力；生成时先按 `local-managed-runtime` 逻辑源建模，落盘时再改写到项目内相对路径
- 若这层能力缺口需要补齐，应回到 `hiui-design` 的受管运行时合同处理，而不是把新能力临时塞进业务组件目录或页面文件里

## 使用顺序

生成或修改页面时，优先按下面顺序执行：

1. 先读本文件，建立组件 / 设计系统基线
2. 再读 `generation-principles.md`，确认页面气质和结构边界
3. 再读 `page-type-map.md`，判断页型
4. 命中页型后，再读 `figma-page-rules.md`
5. 再读对应 `figma-pages/*.md`
6. 最后才选择最近模板页做最小偏移

## 组件 / 设计系统驱动原则

### 1. 先看组件，不先看页面

先识别页面由哪些基础能力组成：

- 导航布局
- 页头
- 查询筛选
- 表单
- 表格
- 列表
- 描述列表
- 抽屉
- 底栏
- 提示与状态

如果这些基础能力没有定清楚，不要直接跳到具体页面模板。

### 2. 先看设计系统，再看模板

先确认：

- 主色、语义色、中性色
- 字阶、字重、间距、圆角、阴影
- 按钮、输入框、表格、Tag、Descriptions 的默认视觉
- 宿主与页面之间的白底 / 灰底关系

这些基线定不住时，复制再多页面模板也会漂。

### 3. 页面模板只是组件组合结果

模板页不是第一层事实。

它只是把组件、布局、交互和视觉规则组合成的一个可复用例子。

因此：

- 模板页可以复制
- 但复制前必须知道它依赖了哪些组件语义
- 复制后只能替换业务槽位，不能改坏底层组件约束

### 4. 先统一组件语义，再统一页型

同一类组件在不同页型里必须保持一致语义：

- 查询筛选里的 Picker 行为一致
- 表格文本列的省略和 Tooltip 一致
- 状态列的 Tag 语义一致
- 表单 label 位置一致
- 抽屉 footer 节奏一致

页型只是这些组件语义的组合容器。

## 和页型层的关系

- 组件 / 设计系统层负责“怎么长”
- 页型层负责“长成哪一类页面”
- 模板层负责“具体复用哪一个页面起点”

如果顺序反了，就会变成：

- 先套页面样板
- 再倒推组件语义
- 最后在局部补丁里修结构

这会让页面越来越像拼装件，不像一个稳定体系。

## 代码修改规则

### A. 组件优先规则

- 新页面先确认用到哪些组件，而不是先选具体模板
- 若组件层已有稳定默认值，页面不得擅自改写
- 若组件层语义冲突，先修组件约定，再落页型模板
- `src/components/hiui-design-runtime` 这层受管公共组件只允许按运行时合同演进；不要把它当成页面级临时 patch 区或业务组件收纳目录

### B. 设计系统优先规则

- 新页面必须继承当前视觉基线
- 不要在页面局部另起一套颜色、字阶、圆角、阴影
- 页面装饰不能替代结构规则

### C. 页型后置规则

- 页型是在组件基线已明确后的组合结果
- 命中页型后才能选母版页
- 模板页只能承载业务替换，不承载新的视觉语法

## 验收用例

### 用例 1：组件语义一致

- 动作：对比多个页面里的同类组件
- 预期：查询筛选、按钮、表格、表单、抽屉保持同一语义

### 用例 2：设计系统一致

- 动作：观察多个页面的颜色、字阶、间距、圆角、阴影
- 预期：整体保持同一 HiUI 5 视觉基线

### 用例 3：页型选择正确

- 动作：把页面先归类到组件与设计系统，再归类到页型
- 预期：页型判断与页面真实结构一致

### 用例 4：模板选择正确

- 动作：在页型已明确后再选母版页
- 预期：模板页与页面结构足够接近，只需最小偏移
