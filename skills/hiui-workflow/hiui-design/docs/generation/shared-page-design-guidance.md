# 页面共享设计指导

## 目标

本文件用于沉淀 `hiui-design` 在典型页面与完全非典型页面之间都必须共享的设计指导。

它解决的是：

- 真实页面变化很大时，哪些结构和视觉规则仍然必须保持稳定
- 典型页面与非典型页面应该先共享什么，再决定走哪条 family / page-type 链路
- 图片、截图和历史页面应该如何被当作事实来源，而不是被误用成新的模板枚举
- 非典型页面即使不走页面模板，字号、颜色、间距、组件和数据图表也必须继续符合 `hiui-design` 规范

它不解决的是：

- 某个典型页型的 `baseTemplatePath`、`businessSlots` 和 `slotBoundaryContract`
- 非典型页面的 `nonTypicalExecutionBrief`、family-specific stop rule 和脚本执行边界
- 某个业务页面的字段、接口、权限和路由细节

## 使用顺序

生成页面时，优先按下面顺序建立上下文：

1. 先读 `design-system-first.md`
2. 再读本文件，锁定跨 family 共享的结构与视觉规则
3. 再读 `hiui5-visual-baseline.md`，补颜色、字阶、间距、按钮、输入和容器默认值
4. 若页面包含图表，再读 `figma-pages/data-visualization.md` 中与图表主题、色板和图表卡约束相关的规则
5. 最后再进入 `generation-principles.md`、`non-typical-design-principles.md` 或命中的具体页型专章

## 一、共享目标

### 1. 页面必须看起来属于同一套产品

- 无论是典型页面还是非典型页面，都必须继续看起来像同一套 B 端系统，而不是另一套后台皮肤
- 结构、信息密度、识别效率和操作稳定性优先于装饰
- 页面变化应优先体现为工作区组合变化，而不是视觉体系变化

### 2. 页面变化不等于页型枚举扩张

- 真实业务图片、截图和历史页面，只能作为事实来源
- 不要把截图中出现的一种排布方式直接沉淀成新的“页面模板”或新的“典型页示例”
- 当页面变化频繁时，优先抽取共享结构语法与视觉语法，而不是追加示例枚举

## 二、共享结构不变量

### 1. 统一页头

- 页面必须存在统一 `PageHeader`
- 页面级标题是全页最高层标题
- 页面级主操作默认优先位于 `PageHeader` 右侧
- 局部模块不得替代页面级标题或主操作入口

### 2. 统一主工作区

- 页面必须存在统一 `whiteBody` 主工作区
- `whiteBody` 是唯一 primary workspace owner，不是任意白色容器
- 不得通过多层白卡叠加伪造第二个同级主工作区
- supporting region 可以存在，但不能替代 primary region

### 3. 单一主阅读流

- 页面必须能够用一句话说明用户从哪里开始、经过哪些主区域、最终完成什么任务
- 页面允许存在主区、上下文区、辅助区、检查区，但只能有一个主阅读流
- 不允许多个同级区域都试图充当“页面主入口”

### 4. 单一主结构

- 页面可以分区，但不得出现第二个同级主结构
- 典型页中的筛选区、表格区、分页区、底栏区，非典型页中的 context / source / primary / supporting region，都必须服从同一主结构
- 不能因为页面复杂，就让多个区域都承担页面主任务的定义权

## 三、共享工作区语法

本层不描述“表格页 / 详情页 / 非典型页”，只描述所有页面都可复用的工作区语法。

### 1. region roles

- `primaryRegion`：承担页面核心任务完成面的唯一主区域
- `contextRegion`：提供稳定上下文，不直接替代主任务完成
- `sourceRegion`：发起主联动的区域
- `supportingRegion`：补充说明、检查、快照或次级协同的区域
- `mutableRegion`：允许按业务内容展开的区域

### 2. coordination rule

- 页面必须能说明哪个区域驱动哪个区域
- 跨区域联动必须是可解释的，不允许仅凭视觉邻近关系假设联动
- 若无法明确主联动关系，说明当前页面结构仍未收敛，不应直接进入生成

### 3. stable vs mutable

- `stableRegions` 描述本次需求中必须保持稳定的结构区域
- `mutableRegions` 描述允许按业务信息展开的区域
- 结构变化优先发生在 `mutableRegions`，而不是页头、主工作区 owner 或主阅读流

## 四、共享视觉与设计系统规则

### 1. surface 关系

- 默认维持“灰底外槽 + 白底主体工作区”
- 主体区强调结构清晰、边界克制，不做 dashboard 化装饰
- 没有书面设计依据时，不得引入彩色卡片墙、重阴影或高装饰背景块

### 2. 字号与标题层级

- 页面级标题、区块标题、子分组标题必须继续使用统一层级
- 字号、字重和层级节奏服从 `hiui5-visual-baseline.md`
- 不得为了突出局部模块，额外发明新的标题档位
- 不得让局部模块标题压过页面级标题

### 3. 颜色、token 与 spacing

- 颜色、字阶、圆角、边框、阴影、间距必须回指到 HiUI5 与 `hiui-design` 基线
- 页面本地样式默认只允许 `layout-only`
- 默认继续使用同一套 spacing scale，而不是按局部视觉感觉自由调整
- 没有明确设计依据时，不得新增页面本地视觉 token
- 模板外新增区域若需要卡片、标签、按钮或标题层级，优先由受管组件自带视觉承载；不要在页面样式里重新声明一套局部视觉规范

### 4. 组件语义

- 基础组件默认继续只允许 HiUI5、`local-managed-runtime` 公开能力和已批准扩展
- 状态表达、按钮优先级、输入控件、卡片边界和常见 tag 语义必须保持一致
- 单维度主切换默认使用 HiUI5 `Radio` 按钮组；只有在交互语义明确属于状态页签或步骤切换时，才使用 `Tabs`
- 不得用 `div/span + className` 伪造语义组件来绕开设计系统
- 若某个区域不在官方模板直接覆盖范围内，也必须先落到受管 runtime primitive 或 HiUI5 公开组件；页面层只允许组合，不允许自由定义新的卡片或视觉语义

### 5. 数据图表也属于设计系统约束

- 页面中一旦出现数据图表，它仍然属于 `hiui-design` 视觉系统的一部分，不是可自由发挥的独立子系统
- 图表的色板、主题、坐标轴、legend、卡片边界、标题字阶、内边距和图表容器节奏，都必须回指到 `hiui-design` 与项目批准的图表主题来源
- 没有明确业务依据时，不得直接回退到图表库默认主题、默认色板或装饰性图表墙
- 图表卡必须继续服从同一 `whiteBody`、同一标题层级、同一 spacing scale 和同一组件语义，不得因为引入图表就另起一套视觉规范
- 只要页面包含图表，就必须至少遵守 `figma-pages/data-visualization.md` 中关于主题来源、色板、图表卡边界、标题层级、内边距和容器节奏的共享规则
- 这条共享图表合同适用于所有含图表页面，不只适用于 `data-visualization` 页型；差别只在于是否需要整页分析布局，不在于图表样式可以放宽
- 若页面以图表为主信息载体，优先回看 `figma-pages/data-visualization.md` 的图表主题、图表卡和 grid 规则；若图表只是非典型页中的局部承载体，不要求复制整页 `data-visualization` 布局，但仍需遵守同一套共享图表合同
- 若使用面积趋势图，必须沿用 `chart-theme.ts` 中受管的面积图合同：通过 `withHiuiResponsiveChart` 包装，使用批准的线宽、渐变填充和透明度；不要直接写裸 `Area` 配置再用 `shapeField: 'smooth'` 拼近似样式
- 图表标题、区块标题和分组标题默认不展示副标题；只有在用户明确要求补充说明、统计口径或阅读提示时，才允许显式开启副标题

## 五、图片与截图使用规则

### 1. 允许提取的内容

- 阅读流
- 区域角色
- 主次任务关系
- 结构层级
- 信息密度
- 视觉强弱

### 2. 不允许直接继承的内容

- 把截图当作新的页面模板
- 把某张图的区块顺序直接命名成新的固定页型
- 把截图中的局部装饰、色块和布局偶然性沉淀成全局规则

### 3. 正确用法

- 图片只用于抽取事实，不用于定义页型
- 样本只能作为某条共享设计语法的证据，不是模板来源
- 若多张图都反复体现同一结构关系，优先沉淀为共享语法，而不是继续补示例

## 六、反模式

- 用“页面很复杂”为理由引入第二套局部视觉系统
- 用多层白卡叠加伪造第二个 `whiteBody`
- 让局部模块标题压过页面级标题
- 让局部按钮区取代页面级主操作
- 用截图枚举替代结构抽象
- 用“非典型页面”作为理由绕开字体、颜色、间距、组件、图表主题或设计系统边界

## 七、family 分流规则

### 1. 进入典型页路径

- 页面仍然可由现有页壳、页型模板或受控局部改造承载
- 单一表格、单一表单或单一详情仍然是主承载体

### 2. 进入非典型页路径

- 多个稳定区域共同承担主任务
- 无法再由单一典型页骨架稳定承载
- 但仍然完全遵守本文件定义的共享结构与视觉语法

### 3. 停在边界判断层

- 无法明确主阅读流
- 无法明确 primary region
- 无法明确 source / target 协同关系
- 页面变化主要只是截图排布变化，而不是结构语法变化
