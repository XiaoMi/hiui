# HiUI 5 典型页视觉与组件基线

## 角色声明

本文件用于承接 HiUI 5 的**视觉气质、颜色层级、字阶和通用组件默认样式**，供典型页生成时复用。

它解决的是：

- 新页面没有逐项设计稿时，典型页仍应保持统一 HiUI 5 视觉基线
- 共享规则里不适合反复展开的颜色、字阶、按钮、输入框、表格默认样式，需要有一个集中参考

它不替代：

- `page-type-map.md` 的页型判断
- `figma-page-rules.md` 的默认 `nodeId` / 页壳注册
- `figma-pages/*.md` 的页型 P0 / 禁止项
- 当前项目 `typical-page-patterns.md` 的代码落地细节

发生冲突时，优先级如下：

1. `figma-pages/*.md`
2. `figma-pages/forms-shared.md` / `figma-pages/table-shared.md`
3. `generation-principles.md`
4. 本文件

## 使用方式

- 命中已有页型时，优先看页型专章；只有需要补视觉与组件默认值时，再回看本文件
- 未命中现成页型时，先读 `design-system-first.md`，再读 `generation-principles.md`，再用本文件补足 HiUI 5 基线
- 不要把本文件当成“所有页面都必须逐字照抄的数值表”；页型专章已有明确规定时，以专章为准

## 页面气质

- 整体应保持 B 端企业系统的克制感，以信息密度、识别效率和操作稳定性优先，不靠装饰制造差异
- 默认视觉关系是“灰底外槽 + 白底主体内容区”，而不是大面积彩色底或强装饰卡片墙
- 主交互色默认只认 HiUI Blue：`#2660FF`；没有书面设计依据时，不要为新页面发明第二套主色
- 语义色只承担语义，不承担主结构装饰：
  - 危险 / 错误：`#FA4646`
  - 成功：`#24B237`
  - 警告：`#FFBD0A`
  - 信息：`#03C1AC`
- 阴影默认应极轻甚至不用；若现有壳层已经是描边白卡，就不要再叠新的强投影

## 颜色基线

### 主交互蓝

- 主按钮 / 激活 / 选中 / 链接：`#2660FF`
- hover：`#4D82FF`
- pressed：`#1843D2`
- 浅色交互底：`#EDF2FF`
- pressed 态浅底 / outline pressed wash：`#E5ECFF`

### 中性色

- 主标题 / 主要正文：`#1A1D26`
- 表单标签 / 次一级正文：`#4E5969`
- 次要说明：`#60636B`
- 占位 / 元信息：`#91959E`
- 禁用文字：`#BABCC2`
- 默认边框 / 分隔线：`#E5E6EB`
- 次级表面 / 表头底：`#F2F3F5`
- 主白底：`#FFFFFF`

### 使用约束

- 典型页默认优先依赖“白底 + 灰底 + 蓝色主交互”三层关系
- 紫色、粉色、靛蓝等强调色不作为典型页主流程结构色；仅在图表、特殊分类或产品明确要求时再使用
- 颜色优先服务语义和层级，不要把颜色当成新的页面分区系统

## 字体与字阶

- 默认 UI 字体：`MiSans VF`
- fallback 可保留：`MiSans, PingFang SC, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`
- UI 层字重默认只用 `400 / 500 / 600`，不要无依据引入 `700`

### 推荐层级

- 页面级标题：`24 / 32 / 600`
- 区块 / 卡片标题：`18 / 26 / 500~600`
- 子分组标题 / 右侧详情主标题：`16 / 22~24 / 500~600`
- 表头 / 分组小标题：`14 / 20 / 600`
- 正文 / 表格单元格 / 普通标签：`14 / 22 / 400`
- 辅助说明 / Tag / 元数据：`12 / 20 / 400~500`

### 使用约束

- 标题应依赖字重和节奏建立层级，不要额外叠很重描边、底纹和装饰块
- 同一页内不要把多个层级都做成 `18px`
- 页面主标题、区块标题、右侧详情标题必须分档；不要把所有标题都做成同一尺寸

## 间距与密度基线

- 典型页默认使用统一 spacing scale 组织元素关系、组件密度和区域层级
- 间距不仅用于“留白”，还用于表达信息亲疏、阅读停顿和视觉分组
- 默认以 `2px` 为最小递进单位，常用档位集中在 `4 / 8 / 12 / 16 / 20 / 24 / 32`
- 元素间距优先使用 `gap` 组织；容器与内容的安全距离优先使用 `padding`
- 没有明确页型依据时，不要按视觉感觉随意发明一套新的 spacing 体系

### 间距 token

- `spacing-0 = 0px`
  语义：无间距
- `spacing-1 = 2px`
  语义：特小间距
- `spacing-2 = 4px`
  语义：超小间距
- `spacing-4 = 8px`
  语义：较小间距
- `spacing-6 = 12px`
  语义：小间距
- `spacing-8 = 16px`
  语义：中等间距
- `spacing-10 = 20px`
  语义：中大间距
- `spacing-12 = 24px`
  语义：大间距
- `spacing-16 = 32px`
  语义：较大间距

### 元素间距推荐

- `4px`
  适用：强关联、紧凑、视觉上几乎不分离的元素
  常见场景：标签内 `icon + text`、按钮内 `icon + text`、搜索框图标与占位文案、树菜单箭头与标题、轻量状态与时间文本
- `8px`
  适用：紧凑但具备呼吸感的同组元素
  常见场景：单选、多选、菜单项、消息提示、标题旁标签、筛选项、同级轻按钮组
- `12px`
  适用：同一区块内的次级分组和较明确的内容切分
  常见场景：按钮与按钮之间、卡片内信息组之间、标题与辅助操作之间、短信息块之间
- `16px`
  适用：上下分布的信息块和模块级分隔
  常见场景：描述列表上下项、工作台模块、主区内较完整的上下区块、分组卡片之间的标准竖向节奏
- `24px`
  适用：更明确的区域分割和表单级分组分离
  常见场景：表单字段组之间、双列表单列组之间、较大的区块切换
- `32px`
  适用：高层级区域切换或大块内容之间的留白
  常见场景：大区块切换、页面级强分组、需要明显停顿的区域边界

### 容器内填充推荐

- `8px`
  适用：轻量、小体量容器
  常见场景：文件列表项、下拉菜单、下拉选择项 list item、轻量操作菜单
- `12px`
  适用：小中型控件
  常见场景：按钮、筛选器、`Select`、`Tooltip` 等组件
- `20px`
  适用：内容型容器和页面级容器
  常见场景：气泡弹窗、卡片、折叠面板、模态框、抽屉、白底主体区、表格和表单所在内容容器

### 使用约束

- 小间距表达强关联，大间距表达弱关联和层级分离
- 同一层级的内容优先复用同一档间距，不要在一页内频繁跳值
- 组件内部优先用 `gap` 管理元素关系，不要用零碎 `margin` 拼节奏
- 容器内边距优先用受管壳层和组件默认值，不要在业务页面里反复补局部 `padding`
- 如果出现“需要靠额外间距补白底、补层级、补滚动”的情况，优先排查页壳、高度链和宿主基线，而不是先把 spacing 当补丁
- 若页型专章已经声明明确间距、`padding`、`gutter`、`rowGap` 或 `columnGap`，以页型专章为准；本节提供的是默认基线

## 按钮基线

- 按钮圆角默认 `6px`
- 高度默认分档：
  - `24px`：超小型行内按钮
  - `28px`：紧凑工具按钮
  - `32px`：默认表单 / 筛选 / 列表操作按钮
  - `40px`：强调级主操作
- 主按钮默认蓝底白字；危险操作默认红底白字；次级操作优先 outline；弱操作优先 text / link
- Link 只用于行内文字动作、跳转和轻交互，不要拿来承担主提交

### 使用约束

- 每个操作区默认最多 1 个主按钮
- 危险按钮只用于删除、移除、停用等破坏性确认，不用于普通导航
- 页头 / 表头操作区若同组存在多个按钮，主按钮仍应放在最右

## 卡片与容器基线

- 默认关系：白卡放在灰底区上
- 默认边框：`1px solid #E5E6EB`
- 圆角：
  - 紧凑卡片：`8px`
  - 标准卡片 / 主体分区：`12px`
- 标准内边距默认 `20px`
- 默认不要依赖重阴影；已有描边白卡足够表达区块层级

### 使用约束

- 卡片是内容分组单元，不是额外装饰
- 不要在典型页里无限嵌套卡片；一般不应超过 2 层
- 若现有固定页壳已承担白底主体，不要再在主体内部重复堆“白卡套白卡”

## 输入框与表单基线

- 默认高度：`32px`
- 小尺寸：`28px`
- 大尺寸：`40px`
- 默认圆角：`6px`
- 默认边框：`1px solid #E5E6EB`
- 正文文字：`14px / 400 / #1A1D26`
- 标签文字：`14px / 400 / #4E5969`
- 占位色：`#91959E`
- focus ring：`0 0 0 2px #BDE2FF`
- disabled：背景 `#F2F3F5`，文字 `#BABCC2`

### 使用约束

- 典型页内优先沿用 HiUI 5 默认输入控件外观；不要为了“统一感”手写一层新的 filled / ghost 语法
- `QueryFilter` / `FilterDrawer` 的展示逻辑优先交给共享适配层或组件默认值，不要把表现层写死进业务字段

## 表格基线

- 表头底色：`#F2F3F5`
- 表头文字：`14px / 600 / #1A1D26`
- 单元格文字：`14px / 400 / #1A1D26`
- 行分隔线：`1px solid #E5E6EB`
- hover 行底：`#F2F3F5`
- selected 行底：`#EDF2FF`
- 默认密度优先 `size="md"`

### 使用约束

- 典型页表格默认追求稳定、易读，不追求高装饰化 striped 视觉
- 若没有页型专章明确要求，默认不单独改小或改大表格密度
- 表格的颜色差异主要用在 hover、selected、状态 Tag，不要把整张表做成多色块信息墙

## Tag / 状态表达基线

- 默认 Tag：浅灰底 + 深色字
- 主状态 Tag：浅蓝底 + 蓝字
- 危险状态 Tag：浅红底 + 红字
- 成功状态 Tag：浅绿底 + 绿字

### 使用约束

- 流程、状态类信息优先用 `Tag`
- 开关、是否、启停类信息默认优先保持文本或受管开关控件语义，不默认做成 `Tag`
- 分类、渠道、入口、是或否等信息默认仍优先纯文本，避免把所有枚举值都做成彩色标签

## 不纳入典型页规则层的内容

下面这些信息保留为 HiUI 5 的通用设计系统背景，不直接纳入典型页生成强约束：

- 顶部导航、侧边导航的具体尺寸与折叠规则
- 品牌展示用字体说明和文档站展示策略
- 图表 / 装饰强调色的完整色阶
- 非典型页专用组件的完整皮肤矩阵

需要这类信息时，优先回 HiUI 5 原始组件文档或项目本地组件知识库，而不是在典型页规则层继续扩写。
