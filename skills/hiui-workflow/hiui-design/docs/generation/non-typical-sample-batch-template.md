# 非典型页面首轮样本验证批量模板

## 目标

本文件用于组织完全非典型页面的首轮批量样本验证。它不是完整验收报告，也不是流程审计表；它只负责把 2 到 3 个真实页面样本收口到同一套判断框架中，避免每个样本重新发明验证口径。

本模板默认保持轻量：

- 先判断样本是否真的属于 `non-typical-page`
- 再看最小决策包是否可形成
- 再看轻量红线是否越界
- 最后汇总哪些规则需要补充、哪些规则不该继续加重

## 批量使用原则

- 首轮只验证 2 到 3 个样本
- 样本之间应覆盖不同复杂度，而不是同一种页面的轻微变体
- 样本验证优先服务“规则修订”，不服务“证明页面已经完美”
- 若样本已经明显不属于完全非典型页面，应直接退出，不强行纳入

## 推荐样本组合

建议首轮至少包含以下三类中的两类，最多三类：

- 样本 A：主任务流明确、结构相对清晰的页面
- 样本 B：主副工作区明显分离的页面
- 样本 C：容易与典型页局部改造混淆的边界页面

不要在首轮批量验证中纳入：

- 纯视觉探索页
- 依赖第三方复杂画布或图形引擎的页面
- 宿主、依赖、样式基线本身尚未稳定的页面

## 产出要求

每一轮批量验证结束后，只保留以下三类产出：

- 一份批量汇总记录
- 每个样本一份单样本记录
- 一份规则修订结论

不要额外新增：

- 大而全的审计报告
- 页面级重验收 checklist
- 把样本直接扩写成新的页面模板枚举或未验证协调模式目录

## 结果解释

- `yes`
  当前批量样本足以支持继续试点，不需要新增重校验
- `partial`
  当前链路可继续，但需要补前置 guidance 或修 stop rule
- `no`
  当前链路尚不足以支撑试点，应先修规则再继续
